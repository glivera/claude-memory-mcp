## Проблема, которую решает апдейт

В оригинальной статье я описал проблему: Claude Code забывает всё между сессиями. Решение — MCP-сервер с векторной памятью.

Но после нескольких недель использования я заметил новую проблему:

**Claude запоминает факты, но не учится на повторяющихся подходах.**

Примеры:
- В каждом проекте я настраиваю Docker одинаково — multi-stage build, Alpine, anonymous volumes для node_modules. Claude каждый раз пишет это с нуля.
- Supabase миграции: каждый раз одна и та же последовательность — pre-flight checks → batched execution → post-flight verification. Claude делает это правильно, но только потому что я описал это в промпте.
- Дебаг API-интеграций: pattern retry-on-429 + exponential backoff встречается в каждом втором проекте.

Эти повторяющиеся подходы — не "воспоминания" (remember хранит факты). Это **навыки** — алгоритмы действий, которые можно формализовать и переиспользовать.

## Что добавлено: Skill Patterns

4 новых инструмента поверх существующих 4 (remember, recall, forget, project_status):

### 1. `pattern_store` — запоминание паттерна

Claude вызывает его когда замечает, что делает что-то повторяющееся. Ключевая механика — **автоматическая дедупликация**:

- Описание паттерна превращается в вектор (тот же OpenAI embedding)
- Если в базе уже есть похожий паттерн (cosine similarity > 0.75) — он не дублируется, а **мержится**: счётчик +1, новый пример добавляется в массив
- Если нет — создаётся новый паттерн со счётчиком 1

Это значит: Claude не надо помнить, сохранял ли он этот паттерн раньше. Он просто вызывает `pattern_store` каждый раз, а система сама разберётся — создать новый или обогатить существующий.

**Пример вызова:**
```
pattern_store(
  description: "Multi-stage Docker builds for Node.js: base stage with dev deps for compile, production stage copies only dist + prod deps",
  category: "devops",
  project: null,  // универсальный паттерн
  example: "В memory-mcp: base stage устанавливает все deps и компилирует TS, production stage копирует только dist/ и устанавливает --production=true. Итоговый образ ~150MB вместо ~800MB"
)
```

### 2. `pattern_search` — поиск по паттернам

Семантический поиск по всем накопленным паттернам. Прежде чем начать нетривиальную задачу, Claude может проверить: "а не делал ли я что-то похожее раньше?"

Поддерживает фильтры по категории, проекту и минимальному количеству повторений.

### 3. `pattern_mature` — зрелые паттерны

Возвращает паттерны, которые были замечены 3+ раз. Это кандидаты на превращение в **Claude Code skill** — формализованный файл SKILL.md, который Claude может выполнять как команду.

Представь: паттерн "настройка Supabase миграции" замечен в 5 разных проектах, с 5 реальными примерами. Из этого можно сгенерировать полноценный скилл с чётким алгоритмом.

### 4. `pattern_mark_as_skill` — пометить как сконвертированный

После генерации SKILL.md, паттерн помечается как `skill_created = true` и перестаёт появляться в списке кандидатов.

## Архитектура (что под капотом)

Всё добавлено как **отдельный слой** поверх существующей системы — ни одна строка старого кода не изменена (кроме 2 строк в index.ts для подключения новых инструментов).

**Новое в базе данных:**
- Таблица `skill_patterns` — 12 колонок, pgvector embedding, JSONB массив примеров
- 4 индекса (vector IVFFlat, category, count, project)
- 2 RPC-функции: `match_skill_patterns` (дедупликация) и `get_mature_patterns` (зрелые паттерны)

**Категории паттернов:**
`n8n` | `supabase` | `devops` | `client` | `content` | `code` | `architecture` | `other`

**Жизненный цикл паттерна:**
```
Замечен впервые (count: 1)
    ↓
Замечен снова (count: 2, merged)
    ↓
Замечен в третий раз (count: 3, proposed_skill: true) ← кандидат на скилл
    ↓
Сгенерирован SKILL.md (skill_created: true) ← готово
```

## Bugfix: forget не мог удалять записи с будущей датой истечения

Попутно нашёл и исправил баг: инструмент `forget` не мог soft-delete записи, созданные с параметром `expires_in_days`. Причина — фильтр искал только `expires_at IS NULL`, но записи с будущей датой имели `expires_at = 2026-04-05` (не null). Исправлено на `expires_at IS NULL OR expires_at > now()`.

## Почему это важно (angle для статьи)

Первая статья была про **память** — Claude запоминает факты.
Этот апдейт про **обучение** — Claude замечает паттерны в собственной работе.

Разница принципиальная:
- Память пассивна: сохранил → нашёл → прочитал
- Паттерны активны: заметил повторение → обогатил примером → предложил формализовать

Это движение от "ИИ с блокнотом" к "ИИ, который строит свою базу знаний". Каждый проект, каждая сессия делает его чуть умнее — не за счёт fine-tuning, а за счёт структурированного опыта.
